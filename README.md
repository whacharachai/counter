# counter.py — โปรแกรมนับจำนวนคน

นับจำนวนคนจากไฟล์วิดีโอ กล้อง หรือสตรีมสด โดยใช้การตรวจจับ (YOLO) + การติดตาม (tracking)
คนแต่ละคนที่ถูกนับจะได้**หมายเลขเฉพาะที่ไม่ซ้ำกัน**แสดงบนเฟรม และระบบจะบันทึกภาพสแน็ปช็อต (jpg) ของคนแต่ละคนไว้

## ภาพรวม

มี 2 โหมดการนับ:

| โหมด | ทำงานอย่างไร | เหมาะกับ |
|------|--------------|----------|
| `line` | กำหนดหมายเลขให้คนแต่ละคน **ครั้งเดียว** เมื่อเส้นทางของคนนั้นข้ามเส้นตรงที่คุณวางไว้บนภาพ | จุดผ่านแบบคงที่: ขอบถนน, ประตู, เส้นทางเดินในทางเดิน |
| `appear` | กำหนดหมายเลขให้ **ทุกคนที่ปรากฏในภาพ** (และอยู่ให้เห็นนานพอ) | ฉากเปิดที่ไม่มีเส้นธรรมชาติ: ห้องโถง, ลานกว้าง, ล็อบบี้ |

กฎความเสถียรของหมายเลข (มีในตัว ไม่ต้องตั้งค่าอะไร):

- หมายเลขจะ **ถูกนำกลับมาใช้ซ้ำ** เฉพาะเมื่อเส้นทางของคนคนเดียวกันหลุดไปชั่วครู่
  (ไม่เกิน `--merge-seconds`) แล้วกลับมาปรากฏในบริเวณใกล้เคียงภายในระยะ `--merge-gap`
- หมายเลขจะ **ไม่ถูกนำกลับมาใช้ซ้ำ** สำหรับคนที่ออกจากขอบภาพ และ
  **คนสองคนที่อยู่พร้อมกันจะไม่มีวันได้หมายเลขซ้ำกัน**

ทุกครั้งที่รัน ระบบจะเขียนไฟล์ `<source>_counter.txt` (`people=N` / `in=N out=N total=N`)
และถ้าใช้ `--save` จะเขียนไฟล์ `<source>_counted.mp4` ด้วย

## การติดตั้ง

### 1. ติดตั้ง Python

ใช้ **Python 3.8 ขึ้นไป** (แนะนำ 3.10–3.12) แล้วตรวจสอบด้วย:

```
python --version
```

### 2. ติดตั้ง library

แนะนำให้สร้าง virtual environment ก่อน เพื่อไม่ให้ library ชนกับโปรเจกต์อื่น:

```
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate  # Linux / macOS
```

ติดตั้งตามไฟล์ `requirements.txt`:

```
pip install -r requirements.txt
```

ประกอบด้วย: `ultralytics` (YOLO), `opencv-python` (อ่าน/ประมวลผลวิดีโอ), `torch` (แบ็กเอนด์)
โดย `ultralytics` จะดึง `torch` และ `opencv-python` มาให้เองอยู่แล้ว

### 3. ติดตั้ง CUDA (ให้ YOLO ใช้ GPU)

YOLO คำนวณบน GPU ผ่าน PyTorch + CUDA:

1. ตรวจว่าไดรเวอร์ NVIDIA รองรับ CUDA เวอร์ชันใด:

   ```
   nvidia-smi
   ```

   อ่านตัวเลขในคอลัมน์ **CUDA Version** ด้านบนสุด (เช่น `13.0`)
2. เปิด <https://pytorch.org/get-started/locally/> เลือก OS ของคุณ แล้วเลือก
   เวอร์ชัน CUDA ที่**ต่ำกว่าหรือเท่ากับ**ที่ไดรเวอร์รองรับ แล้วคัดลอกคำสั่งติดตั้งมาใช้
   (สังเกตส่วน `--index-url https://download.pytorch.org/whl/cuXXX`)

   ตัวอย่างสำหรับ CUDA 13.0 บน Windows:

   ```
   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
   ```

   หมายเหตุ: ถ้า `pip install torch` ตามปกติจาก PyPI บน Windows/Linux ก็จะได้เวอร์ชัน
   ที่รองรับ CUDA อยู่แล้ว (ใช้ GPU ได้ทันทีถ้ามีไดรเวอร์) — วิธีด้านบนไว้สำหรับเลือก
   เวอร์ชัน CUDA เฉพาะ หรือดาวน์โหลด CPU-only ได้จาก `--index-url https://download.pytorch.org/whl/cpu`
3. ตรวจสอบว่า GPU ใช้ได้:

   ```
   python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
   ```

   ถ้าได้ `True ...` แปลว่าใช้ GPU ได้ แล้วรันโปรแกรมด้วย `--device 0` (หรือ `--device cuda:0`)

4. ถ้าไม่มี GPU ก็ใช้ CPU ได้ด้วย `--device cpu` แต่อาจช้ากว่า 5–10 เท่า

### 4. ทดสอบการติดตั้ง

รันพรีวิวสั้น ๆ เพื่อให้แน่ใจว่าทุกอย่างทำงาน:

```
python counter.py --source test_video.mp4 --mode appear --show --max-frames 120
```

## พารามิเตอร์

### ไฟล์เข้า / ไฟล์ออก

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--source` | `0` | ที่อยู่ของไฟล์วิดีโอ, หมายเลขกล้อง (เช่น `0`, `1`), หรือ URL ของสตรีม (`http://…`, `rtsp://…`) |
| `--model` | `yolov8n.pt` | ไฟล์โมเดล YOLO ยิ่งใหญ่ยิ่งแม่นแต่ช้าลง `yolov8n.pt` (เร็ว), `yolov8m.pt`, `yolo26x.pt` (แม่นสุด ช้าสุด) ดาวน์โหลดอัตโนมัติเมื่อใช้ครั้งแรก |
| `--device` | auto | อุปกรณ์สำหรับคำนวณ: `0` / `cuda:0` สำหรับ GPU, `cpu` สำหรับ CPU |
| `--save` | off | บันทึกวิดีโอที่มีกรอบกำกับไว้ที่ `<source>_counted.mp4` ส่วนไฟล์ counter txt เขียนไว้เสมอไม่ว่าจะเปิดหรือปิด |
| `--no-snapshots` | off | สแน็ปช็อตเปิดเป็นค่าเริ่มต้น Flag นี้ใช้ปิดการบันทึกภาพ jpg ของแต่ละคน ไฟล์จะตั้งชื่อเป็น `<id>_MM_SS.jpg` (เช่น `7_01_23.jpg`) โดยเวลาในชื่อคือตำแหน่งในวิดีโอ |
| `--max-frames` | `0` | หยุดหลังประมวลผล N เฟรม (`0` = ไม่จำกัด) ใช้ค่าที่น้อยเพื่อพรีวิววิดีโอยาว ๆ อย่างรวดเร็ว |

### โหมดการนับ

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--mode` | `line` | `line` หรือ `appear` (ดูตารางด้านบน) |
| `--line` | `0.5` | ตำแหน่งของเส้นนับเป็นเศษส่วนของแกนที่เลือก (0–1) |
| `--line-axis` | `horizontal` | `horizontal` (เส้นจากซ้ายไปขวา) หรือ `vertical` (เส้นจากบนลงล่าง) |
| `--in-direction` | auto | ทิศทางที่ข้ามเส้นเส้นไหนนับเป็น `in`: `top-to-bottom`, `bottom-to-top`, `left-to-right`, `right-to-left` ค่าเริ่มต้น: `top-to-bottom` สำหรับเส้นแนวนอน, `left-to-right` สำหรับเส้นแนวตั้ง เลือกให้ตรงกับมุมมองกล้องของคุณว่าแบบไหนคือ "เข้าประตู" |
| `--count` | `both` | เฉพาะโหมด line: `both` นับทุกการข้าม, `in` นับเฉพาะคนเข้า, `out` นับเฉพาะคนออก |

### การตรวจจับ / การติดตาม

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--conf` | `0.25` | ค่าความมั่นใจของการตรวจจับ เพิ่มเป็น `0.35–0.4` เพื่อลดการตรวจจับผิด; ลดลงถ้าพลาดคน |
| `--min-size` | `0` | ไม่สนใจการตรวจจับที่มีด้านสั้นของกล่องเล็กกว่าเศษส่วนนี้ของด้านสั้นของเฟรม เช่น `0.05` = ข้ามคนที่เล็กกว่า 5% ของความสูงเฟรม — ใช้กรองคนที่อยู่ไกล/เล็ก (รวมถึง false positive) ในฉากถนน `0` = ปิด |
| `--imgsz` | `640` | ขนาดภาพสำหรับการคำนวณ เพิ่มเป็น `1280` เมื่อคนเล็ก/อยู่ไกล (ฉากถนน, แหล่ง 4K); `640` มักพอใช้เมื่อคนอยู่ใกล้ |
| `--tracker` | auto | ไฟล์ config ของ tracker (yaml) `cfg/bytetrack_strong.yaml` ทำให้ track ID คงอยู่ได้นานขึ้น ช่วยในที่คนเยอะ/มีการบดบัง และแหล่งที่ fps ต่ำ จะถูกใช้โดยอัตโนมัติเมื่อ `--stride` มากกว่า `>1` |
| `--rtsp-tcp` | off | บังคับใช้ TCP สำหรับสตรีม RTSP (เสถียรกว่าบน Windows เมื่อเทียบกับ UDP เริ่มต้น) |

### ความเร็ว

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--stride` | `1` | ประมวลผลทุก ๆ เฟรมที่ N เพื่อความเร็วขึ้นประมาณ N× เฟรมที่ข้ามจะถูก grab แต่ไม่ decode เมื่อ `>1` จะเปิด strong tracker (`cfg/bytetrack_strong.yaml`) โดยอัตโนมัติ — ที่ fps ที่มีผลต่ำ tracker เริ่มต้นจะแยกคนคนเดียวเป็นหลาย track และแต่ละส่วนจะได้หมายเลขใหม่ ดูหัวข้อ "ทำอย่างไรให้เร็วขึ้น" ด้านล่างสำหรับการแลกความแม่นยำที่เหลืออยู่ |
| `--half` | off | การคำนวณ fp16 half-precision บน GPU ช่วยมากกับโมเดลใหญ่; ไม่มีผลบน CPU |

### การปรับจูนโหมด appear / การรวมหมายเลข

ค่าเหล่านี้สำคัญเฉพาะโหมด `appear` ทั้งสามค่าปรับอัตโนมัติจากวิดีโอ ตั้งเองก็ต่อเมื่อพฤติกรรมอัตโนมัติต้องปรับ

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--appear-seconds` | auto `0.25` | คนต้องปรากฏนานแค่ไหนถึงจะถูกนับ เพิ่มขึ้นเพื่อข้ามคนที่แค่เดินผ่าน/แวบเข้ามา; ลดลงเพื่อนับคนที่เดินผ่านเร็ว |
| `--merge-seconds` | auto `0.8` | ช่วงเวลากรุณา (วินาที) ที่จะนำหมายเลขของคนกลับมาใช้ซ้ำเมื่อ track ของเขาหลุดไปแล้วกลับมาใกล้ ๆ เพิ่มถ้า tracker เสียคนไปนานกว่านี้แล้วยังอยากให้ได้หมายเลขเดิม |
| `--merge-gap` | auto | ระยะทางสูงสุดในการรวมกันเป็นเศษส่วนของความกว้างวิดีโอ ประเมินอัตโนมัติจากความกว้างของคน (clamp 0.03–0.07) ตั้งเอง (เช่น `0.05`) เพื่อควบคุมว่า track ที่กลับมาอยู่ "ใกล้" แค่ไหนถึงจะรวมกัน |

### การแสดงผล

| Flag | ค่าเริ่มต้น | ความหมาย |
|------|---------|---------|
| `--show` | off | แสดงวิดีโอที่มีกรอบกำกับในหน้าต่าง (กด `q` เพื่อออก) |

## พารามิเตอร์แนะนำตามสถานการณ์

### 1. ทางม้าลาย / ถนน (ทางแยก / จุดข้ามถนน)

คนมักเล็ก เคลื่อนที่สม่ำเสมอ ข้ามขอบถนนที่เป็นจุดคงที่

```
counter.py --source street.mp4 --mode line --model yolo26x.pt --imgsz 1280 --show --save
```

- `--mode line` — มีจุดข้ามที่เป็นธรรมชาติ
- `--line 0.5 --line-axis horizontal` — วางเส้นขวางถนน; ปรับ `--line` ให้ตรงขอบถนนจริง
- `--imgsz 1280` — คนเดินถนนที่ไกล/เล็กต้องใช้ความละเอียดสูงขึ้น
- `--model yolo26x.pt` — ความแม่นยำสำคัญกว่าความเร็วตรงนี้
- `--conf 0.25` — ค่าเริ่มต้น; เพิ่มเป็น `0.3` ถ้าวัตถุเล็กทำให้เกิด false positive
- `--min-size 0.03–0.05` — ถ้าไม่ต้องการนับคนเล็กที่อยู่ไกล (หรือ false positive ของมัน)
  ให้ตั้งขนาดกล่องขั้นต่ำ เช่น `0.03` = นับเฉพาะคนที่สูงอย่างน้อย 3% ของความสูงเฟรม
- `--tracker cfg/bytetrack_strong.yaml` — แนะนำถ้าเป็นถนนที่พลุกพล่าน
  (มีการบดบัง, คนข้ามกัน) เพื่อให้ ID คงที่ จะเปิดอัตโนมัติเมื่อ `--stride > 1`

เวอร์ชันเร็ว / real-time: `--model yolov8n.pt --imgsz 640`

### 2. ห้องโถง / พื้นที่เปิดในอาคาร (คนเคลื่อนที่อิสระ ไม่มีเส้น)

ไม่มีเส้นข้ามธรรมชาติ — นับทุกคนที่เข้ามาในภาพ

```
counter.py --source hall.mp4 --mode appear --model yolov8n.pt --imgsz 640 --show --save
```

- `--mode appear` — นับทุกคนที่ปรากฏตัว
- `--imgsz 640` — คนมักอยู่ใกล้กล้องและใหญ่พอ
- `--merge-seconds 0.8` (auto) — ใช้ค่าเริ่มต้น; ในห้องโถงคนจะบดบังกัน
  และช่วงกรุณาจะทำให้กลับไปใช้หมายเลขเดิม
- สแน็ปช็อตเปิดเป็นค่าเริ่มต้น ดังนั้นคุณดูได้ในโฟลเดอร์ `hall/` ว่าใครถูกนับไปบ้าง

ถ้าคนจำนวนมากแค่เดินผ่านภาพเร็ว ๆ และไม่ควรนับ ให้เพิ่ม
`--appear-seconds` เป็น `0.5–1.0`

### 3. ทางเข้าประตู (คนเดินผ่านช่องประตู)

เป็นคอขวดคงที่ — ใช้เส้นขวางช่องเปิดพอดี

```
counter.py --source door.mp4 --mode line --line 0.5 --line-axis horizontal --model yolov8n.pt --imgsz 640 --show --save
```

- `--mode line` — ช่องประตูคือจุดข้าม
- `--line` / `--line-axis` — วางเส้นขวางช่องประตู ถ้ากล้องมองประตูจากด้านบนหรือด้านข้าง
  อาจใช้ `vertical` เข้ากว่ากัน (ขอบแนวตั้งของประตู)
- `--tracker cfg/bytetrack_strong.yaml` — คนจะถูกบดบังชั่วครู่ขณะผ่าน
  strong tracker ช่วยไม่ให้นับซ้ำ

**แยกคนเข้า vs คนออก:** โหมด `line` แสดงทั้งสองอยู่แล้ว — ตัวนับบนจอแสดง
`In: X  Out: Y  Total: Z` และไฟล์ counter txt เขียน `in=N out=N total=N`
ค่าเริ่มต้นของ "in" หมายถึง "ข้ามเส้นจากบนลงล่าง" (สำหรับเส้นแนวนอน);
ใช้ `--in-direction` เพื่อให้ตรงกับมุมมองกล้องประตูของคุณ:

```
counter.py --source door.mp4 --mode line --line 0.5 --in-direction bottom-to-top --show --save
```

- `--in-direction bottom-to-top` → คนที่ขยับขึ้นบนข้ามเส้นจะถูกนับเป็น `in`
  (เช่น เข้าห้องเมื่อประตูอยู่ด้านล่างของภาพ) สำหรับเส้นแนวตั้งใช้
  `--in-direction left-to-right` / `right-to-left`

**นับเพียงทิศทางเดียว (เช่น ประตูเฉพาะทางเข้า):**

```
counter.py --source door.mp4 --mode line --line 0.5 --in-direction bottom-to-top --count in --show --save
```

- `--count in` นับเฉพาะคนเข้า (`out` คงเป็น 0); `--count out` นับเฉพาะคนออก

เวอร์ชันเร็วที่ใช้แค่กล้อง: `--source 0`

## ทำอย่างไรให้เร็วขึ้น

เวลาประมวลผลส่วนใหญ่มาจากการคำนวณ YOLO (วัดได้ที่ประมาณ ~30 fps สำหรับ
`yolov8n` ที่ `640` บน RTX 4060) คันโยกที่ได้ผลจริงมีแค่ `--stride`

```
counter.py --source video.mp4 --mode appear --stride 3 --show
```

- `--stride N` สุ่มตัวอย่างวิดีโอที่ `fps / N` — นี่คือการเพิ่มความเร็วทั้งหมด
  (ประมาณ N×) และเป็นต้นทุนด้านความแม่นยำทั้งหมดด้วย สิ่งที่ตัวสุ่มตัวอย่างไม่เคยเห็นก็ไม่ถูกนับ:
  - **โหมด appear:** ใช้ `--stride 2–3` strong tracker จะถูกเลือกให้โดยอัตโนมัติ
    เพื่อไม่ให้คนถูกแยกเป็นหลาย track/หมายเลข; คนที่อยู่ในภาพหลายวินาทีจะยังถูกนับ
    ส่วนคนที่ผ่านเร็วมาก (แค่เสี้ยววินาที) อาจพลาด — อย่าเกิน 3 สำหรับฉากที่พลุกพล่าน
  - **โหมด line (ประตู/ทางข้าม):** ใช้ร่วมกับ
    `--tracker cfg/bytetrack_strong.yaml` การตรวจจับการข้ามต้องเห็นคนคนเดียวกัน
    ก่อนและหลังเส้น ดังนั้น stride ที่แรง (4–5) ปลอดภัยเฉพาะฉากช้า ๆ ที่คนไม่หนาแน่น
    เริ่มที่ `--stride 2–3`
- `--half` เปิดการคำนวณ fp16 บน GPU ช่วยได้น้อยกับ `yolov8n` บน GPU เครื่องนี้
  แต่ลองได้กับโมเดลใหญ่ ๆ (`yolov8m.pt`, `yolo26x.pt`)
- เมื่อความแม่นยำสำคัญกว่า ควรเลือก `--model` ที่ใหญ่กว่าที่ `--stride 1` แทนที่จะใช้ `--stride` สูง
  — ความแม่นยำจากโมเดลที่แข็งแกร่งกว่าเหนือกว่าความแม่นยำจากความหนาแน่นของการสุ่มตัวอย่าง

ตรวจสอบ stride ที่เลือกด้วยการพรีวิวสั้น ๆ ก่อน:
`counter.py --source clip.mp4 --mode appear --stride 3 --max-frames 200 --show`

---

## ขั้นตอนการใช้งานโดยทั่วไป

1. **พรีวิว** ส่วนสั้น ๆ เพื่อยืนยันการตรวจจับ:
   `counter.py --source clip.mp4 --show --max-frames 120`
2. **ปรับ** โหมด ตำแหน่งเส้น และ `--imgsz`/`--model` ให้เข้ากับฉากของคุณ
3. **รัน** ด้วย `--save` เพื่อได้วิดีโอที่มีกรอบกำกับ; ตรวจสแน็ปช็อตในโฟลเดอร์
   `<source>/` เพื่อยืนยันคนที่ถูกนับแต่ละคน
4. อ่านจำนวนสุดท้ายจาก `<source>_counter.txt`
